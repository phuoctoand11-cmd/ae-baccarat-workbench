# AE Baccarat Workbench

Tool desktop Windows cho AE SEXY Baccarat theo hướng **live monitor + signal + paper trading**. Bản đầu tiên cố ý **không auto-bet**: chỉ đọc dữ liệu, tạo tín hiệu, mô phỏng vốn và ghi audit.

## Mục tiêu MVP

- Quét nhiều bàn AE SEXY qua Chrome CDP/Playwright khi có dữ liệu WS/roadInfo.
- Nhập tay chuỗi `B P T` để test nhanh khi chưa nối live.
- Tạo tín hiệu từ các nhóm chiến lược ban đầu:
  - CSSS/SCCC theo streak/chop.
  - Run length.
  - Shoe profile cơ bản.
  - Sequence follow.
  - Ensemble majority.
- Paper trading với flat/stake chain, stop-loss, take-profit, group TP/SL.
- Lưu SQLite runtime và mirror DuckDB nếu cài `duckdb`.
- Giao diện tiếng Việt bằng `tkinter`, chạy được trên Windows không cần Electron.

## Live auto-update read-only

Live monitor now reads from three passive sources in the Chrome tab:

- WebSocket frames from Chrome CDP.
- XHR/Fetch response bodies that look like table/road JSON.
- Page `localStorage`, `sessionStorage`, and inline JSON scripts that contain road data.

It deduplicates table snapshots before sending them to the engine, so repeated
DOM polling does not create duplicate rounds/signals. The app still never
clicks, fills forms, places chips, stores casino credentials, or bypasses
captcha/anti-bot.

Recommended live flow:

```powershell
chrome.exe --remote-debugging-port=9222 --user-data-dir="%LOCALAPPDATA%\AEBaccaratWorkbench\chrome-profile"
python -m ae_baccarat_workbench
```

Then log in manually in that Chrome window, open the AE SEXY Baccarat lobby or
table, and press **Bat dau CDP** in the Live Monitor tab. If the table stream
uses a different payload shape, capture a sample frame/body and add a focused
decoder test in `tests/test_ae_decode.py`.

Optional auto refresh:

- In the Live Monitor tab, enable **Auto refresh** and enter the number of
  seconds between page reloads.
- The minimum accepted interval is `30` seconds.
- The monitor reloads detected live baccarat pages, including the outer
  `live-dealer` page, the AE/SEXY popup, and provider iframe hosts like
  `sfcdf.*`, then continues listening to CDP data.
- Pressing **Bat dau CDP** now saves the auto-refresh setting to
  `config.local.json`, so reopening the app keeps the same setting.
- It still does not click, fill forms, place chips, store credentials, or bypass
  captcha/anti-bot.

## DuckDB analytics

DuckDB is forced on by app config when the `duckdb` package is installed. SQLite
remains the source of truth, and the app backfills `data/analytics.duckdb` from
SQLite on startup when row counts differ.

Base tables in DuckDB:

- `tables`: table identity and last-seen metadata.
- `rounds`: full decoded result history for every scanned table.
- `signals`: every strategy signal generated by the engine.
- `paper_bets`: settled paper-trading history with stake, result, and P&L.
- `latency_samples`: passive monitor timing samples from CDP callback through
  app queue, engine processing, and UI refresh.

Analytics views:

- `paper_bet_results`: adds `wl_result`, `is_win`, `is_loss`, `is_push`, and
  `pnl_result`.
- `paper_wl_streaks`: per-table/per-strategy win/loss streak length.
- `round_streaks`: per-table/per-shoe Banker/Player/Tie result streak length.
- `table_round_summary`: result counts and first/last seen by table.
- `strategy_performance`: win rate, P&L, max win streak, and max loss streak by
  table and strategy.
- `ml_rolling_features`: ML-ready training rows with only pre-signal table,
  shoe, and strategy history.

The live provider may send either full road history or only the latest result.
When only latest results are available, the app still uses `round_no`/`gameRound`
as the current shoe position. Dashboard round counts display as `current/saved`
when early results are missing, for example `61/50`.

Near-end shoe protection is configurable:

- `expected_shoe_rounds`: default `72`.
- `stop_signals_after_round`: default `65`; the app keeps saving results but
  skips new signals/paper bets once the current round reaches this value.

The multi-table dashboard shows the full current-shoe road in **KQ bàn**. When a
new shoe starts, the visible road resets for that table, while historical rounds
remain stored for analytics and ML. Dashboard ML streak columns use only settled
paper bets whose reason starts with `ML pass:`. Skipped ML predictions and push
results do not break the displayed ML W/L streak; the **Dự đoán W/L ML** column
shows the recent W/L source sequence used to produce **Chuỗi W/L ML**. The
**Tổng ML Pass** row sums all settled ML Pass wins, losses, pushes, and Paper
P&L across every table.

When multiple strategies receive an ML Pass on the same table and same
`signal_fingerprint`, paper trading arms only the highest-probability strategy.
All strategy signals are still saved for analytics, but the dashboard ML W/L
sequence and total row count only one selected ML Pass per prediction.

The `W/L ML >=7` tab shows only live dashboard rows whose current
**Chuoi W/L ML** value is `W7`/`L7` or higher. It uses the same columns as the
multi-table dashboard and refreshes from the same live data.

Live table rows are hidden from the dashboard when they have not updated for
`live_table_stale_seconds` seconds, default `120`. This only filters the UI:
stored history remains available for analytics/ML, and the table appears again
automatically when CDP receives a fresh snapshot for it. Set the value to `0`
to disable stale-table hiding.

## Daily paper experiment

The `Paper theo khung giờ` tab runs three local Vietnam-time paper sessions:
`12:00-13:00`, `14:00-15:00`, and `18:00-20:00`. Each session automatically
records at most two fresh ML Pass candidates. A table can be recorded only once
per local day, even if it qualifies again in a later session.

The experiment is independent from the normal `paper_bets` ledger. It stores
the actual source strategy, ML probability, stake, signal fingerprint, result,
and P&L in `daily_experiment_bets`. Settlement uses the first stored physical
round after the signal fingerprint, so a pending experiment can still settle
after an app restart. This feature is paper-only and never clicks or places a
real bet in the browser.

## Passive latency monitor

The desktop app has a `Latency` tab. It records one `latency_samples` row for
each decoded snapshot after the UI refresh completes. Columns split the timing
into queue delay, engine processing, UI refresh delay, and total time. The first
measured point is the app's CDP callback, not a casino-server timestamp.

## Offline ML baseline

Install the optional ML stack:

```powershell
pip install -e ".[ml]"
```

Export DuckDB features only:

```powershell
python -m ae_baccarat_workbench.ml --features-only
```

Train the first baseline models:

```powershell
python -m ae_baccarat_workbench.ml --min-rows 30
```

Evaluate the trained model:

```powershell
python -m ae_baccarat_workbench.ml --evaluate --model xgboost --decision-threshold 0.55
```

The ML pipeline reads `ml_rolling_features`, built from the DuckDB history views
with a strict pre-signal rule: a row can use only table/shoe results already
visible at that signal and strategy paper bets with `settled_at < created_at`.
It trains a scikit-learn logistic baseline and an XGBoost classifier when
`xgboost` is installed. Outputs are written to `data/ml/`:

- `training_features.csv`
- `training_metrics.json`
- `sklearn_logistic.joblib`
- `xgboost.joblib`
- `evaluation_thresholds_xgboost.csv`
- `evaluation_by_strategy_xgboost.csv`
- `evaluation_by_table_xgboost.csv`
- `evaluation_report_xgboost.md`

Close the desktop app before running offline ML if DuckDB reports a file lock.
The target is settled paper-bet win/loss (`target_win`), so this is for offline
analytics and paper validation only. Audit columns such as `wl_result`,
`settled_outcome`, `pnl_delta`, and `pnl_after` are exported but excluded from
model features.

## Live ML filter

The desktop app can load the trained model as a live signal filter. This is not
an auto-bet executor: strategies still create the original signal, then ML adds
`ml_probability_win` and either keeps the signal or converts it to `skip` before
paper trading is armed.

Config keys:

- `ml_filter_enabled`: default `true`.
- `ml_model_path`: default `data/ml/xgboost.joblib`.
- `ml_decision_threshold`: default `0.55`.

If the model file or ML packages are missing while ML filtering is enabled, the
app logs `ML filter NOT ready` and skips new paper bets instead of letting
unreviewed signals enter pending. Disable `ml_filter_enabled` in the Config tab
only when you intentionally want the normal strategy-only flow. Changing the
model path or threshold and pressing **Lưu cấu hình** reloads the filter
immediately.
